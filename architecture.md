# Архитектура системы управления задачами (Todo-лист)

## Классы и их назначение

- `Task` — отдельная задача. Хранит все данные о задаче и умеет менять своё состояние.
- `Project` — проект/категория. Содержит список задач, группирует их, управляет жизненным циклом задач внутри проекта.
- `User` — пользователь системы. Хранит профиль и список своих проектов, управляет доступом к проектам.
- `TodoManager` — центральный менеджер системы. Координирует работу между классами, реализует бизнес-логику (валидации, проверки дедлайнов, статистику).

---

## Атрибуты (данные) классов

### Task
- `id` (уникальный идентификатор)
- `title` (название задачи, строка)
- `description` (описание, строка, может быть пустым)
- `status` (статус: `"new"`, `"in_progress"`, `"done"`, `"cancelled"`)
- `priority` (приоритет: `1` (низкий) — `5` (высокий))
- `due_date` (дедлайн, дата/время, может отсутствовать)
- `created_at` (дата создания)
- `assigned_to` (ссылка на `User`, кому назначена задача; может быть `null`)

### Project
- `id` (уникальный идентификатор)
- `name` (название проекта)
- `owner` (владелец проекта — ссылка на `User`)
- `members` (список участников проекта — список ссылок на `User`)
- `tasks` (список задач проекта — список объектов `Task`)
- `is_archived` (флаг: архивирован ли проект)

### User
- `id` (уникальный идентификатор)
- `username` (логин/имя пользователя)
- `email` (почта)
- `projects` (список проектов, где пользователь участвует)
- `preferences` (настройки: язык, часовой пояс, уведомления и т.п.)

### TodoManager
- `users` (словарь/коллекция пользователей по `id`)
- `projects` (словарь/коллекция проектов по `id`)
- `tasks` (словарь/коллекция задач по `id`)

---

## Методы (действия) классов

### Task
- `mark_as_done()` — переводит статус в `"done"`
- `mark_as_cancelled()` — переводит статус в `"cancelled"`
- `start_work()` — переводит статус в `"in_progress"`
- `change_description(new_text)` — обновляет описание
- `set_due_date(date)` — устанавливает дедлайн
- `set_priority(level)` — устанавливает приоритет
- `is_overdue()` — возвращает `true`, если дедлайн прошёл и статус не `"done"`

### Project
- `add_task(task)` — добавляет задачу в проект
- `remove_task(task_id)` — удаляет задачу из проекта
- `get_tasks_by_status(status)` — возвращает задачи по статусу
- `get_overdue_tasks()` — возвращает просроченные задачи
- `archive()` — архивирует проект (`is_archived = true`)
- `invite_member(user)` — добавляет участника в проект

### User
- `create_project(name)` — создаёт новый проект, становится его владельцем
- `join_project(project_id)` — присоединяется к проекту (если есть приглашение)
- `update_preferences(new_prefs)` — обновляет настройки
- `get_assigned_tasks()` — получает список задач, назначенных пользователю

### TodoManager
- `create_task(title, project_id, user_id?)` — создаёт задачу, связывает с проектом и пользователем
- `complete_task(task_id)` — завершает задачу через вызов `mark_as_done`
- `move_task_to_project(task_id, new_project_id)` — перемещает задачу между проектами
- `search_tasks(query, filters)` — ищет задачи по тексту и фильтрам (статус, приоритет, дедлайн)
- `generate_report(user_id, period)` — формирует отчёт по задачам пользователя за период
- `check_overdue_and_notify()` — проверяет просроченные задачи и готовит уведомления

---

## Взаимодействие объектов

- Пользователь (`User`) создаёт проект через `TodoManager.create_project()`. `TodoManager` создаёт объект `Project`, назначает владельцем `User`, добавляет проект в коллекцию `projects`.
- Пользователь добавляет задачу: вызывает `TodoManager.create_task()`, передавая `title`, `project_id` и, при необходимости, `user_id`. `TodoManager` создаёт `Task`, связывает его с `Project` (добавляет в `Project.tasks`) и, если указан, назначает на `User`.
- Задача живёт внутри проекта: `Project` управляет своим списком `tasks`, фильтрует и группирует их. При удалении проекта задачи либо перемещаются в архив, либо удаляются (зависит от политики).
- Статус задачи меняется через методы `Task` (`mark_as_done`, `start_work` и т.д.). Проект может проверять просроченные задачи через `Task.is_overdue()`.
- `TodoManager` выступает единым интерфейсом для всей системы: он не дублирует логику классов, а делегирует операции соответствующим объектам и следит за согласованностью данных (например, чтобы задача не оказалась в двух проектах одновременно).
- Уведомления и отчёты строятся на основе данных из `Task`, `Project`, `User`: `TodoManager` собирает нужные задачи, проверяет статусы и дедлайны, формирует итоговые данные.
